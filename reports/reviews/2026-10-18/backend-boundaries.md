# Backend and shared boundary review — 18 October 2026

Scope: inventory of all tracked server/, shared/, api/ files, with direct inspection of authentication, routing, persistence, evidence, transport, commerce, onboarding, migration, jobs and policy boundaries. This is source and focused regression evidence; it does not certify unconfigured external providers or the production Supabase schema.

## Fixed and regression verified

- HIGH: any signed-in customer could read every business freight shipment, create freight records and obtain business aggregate counts through founder-assistant proposals. Canonical HTTP routes now require founder authority (app.ts routes). Shipment schema contains no ownership/outlet scope, so extending staff access would grant global business access. Freight status route also matched the wrong path segment and never reached the updater; corrected.
- HIGH: Workspace execution generated a completed external receipt and a Google preview URL without a provider call. Consent still records correctly; execution now returns WORKSPACE_UNAVAILABLE and creates no receipt. Consent scopes are allowlisted at runtime.
- HIGH: onboarding trusted string/fraction prices and opening quantities, reset existing SKU revisions and duplicated opening inventory on packet retry. Added shape/range checks, atomic packet receipts, existing-SKU conflict, and explicit rejection of ambiguous opening quantities across multiple products. Existing stock is preserved; normal catalogue edits continue through versioned canonical commands.
- HIGH: migration rollback deleted subsequently changed orders and could leave linked cases/payments orphaned. New receipts record exact imported-order hashes; rollback checks source hash plus dependencies and atomically refuses changed, linked or legacy unprovenance receipts.
- MEDIUM: provider POST webhook was rejected by the browser Origin policy and reconstructed JSON before signature verification. Exact raw UTF-8 bytes now reach signature validation on a narrow callback branch with body limits, rate limits and an atomic processing transaction. Other POSTs retain Origin/CSRF checks. Missing transport cannot verify using a default token.
- MEDIUM: runtime health called cloud persistence LOCAL_SQLITE. Explicit persistenceMode supports SUPABASE_SNAPSHOT without exposing credentials.

Evidence: observed failing regressions before fixes for customer access (200 instead of 403), real signed callback without Origin (403 instead of 200), invented Workspace success, invalid numeric onboarding, duplicate inventory and destructive rollback. After changes, 29 tests / 177 assertions across six focused files passed; later added health test passed with the backend-security file (4 tests / 29 assertions). ## Remaining functional boundaries and risks

1. HIGH functional: Vercel API does not run server/index.ts's recurring local job worker. Jobs can queue indefinitely in cloud. No cron or durable cloud worker was added here. Automation definitions can show enabled, but no scheduler consumes these definitions. These must remain explicitly unavailable/pending until implemented and verified.
2. HIGH when external transports are enabled: WhatsApp sendTemplateMessage and Automation.publishPostiz send before a durable intent reservation. Parallel calls with the same key can create duplicate provider effects, and authorization can be revoked while awaiting the provider. Production cloud factory omits these transports, so do not enable them without an outbox/intent lease and provider idempotency.
3. MEDIUM integrity: onboarding accepts and validates dealerTerms and locations, but original implementation does not save them into canonical business settings. locationsCount reports packet count. Stock is persisted but business location/terms approval requires the existing Settings flow. Do not describe this as completed onboarding of those settings.
4. MEDIUM: LegacyPilots.executeFounderProposal only changes proposal status to executed; it does not execute the proposed review/draft command. Treat it as a manual proposal acknowledgement until connected to canonical commands; UI must not promise a real provider effect.
5. MEDIUM: local runtimeTransports implementations fabricate Hermes artifacts, public research snippets, Postiz publication URLs and WhatsApp sent receipts. They are fixtures/pilots and are not injected by the production API or current canonical local server. Never inject createDefaultAutomationOptions/createDefaultWhatsAppTransport as production adapters.
6. MEDIUM operational: asset bundle permits up to 32 MiB and local evidence up to 10 MiB, while Vercel Functions response/request limits are smaller. Production API caps input to 4 MB. Large downloads/asset bundles need bounded refusal or a private Storage delivery design, not a claim of support.
7. LOW observability: production createPlatformApp has no log callback, so redacted request IDs are returned but canonical errors are not persistently logged. A redacted logger is safe to add separately.
8. Migration input maps historical Delivered to verified payment and assigns each parsed line the whole order price. Import metadata is historical, not contemporary payment proof or normalized line accounting. Verify source provenance before business import; rollback protections do not establish historical truth.

## Positive boundary evidence

Password hashes use salted scrypt; unknown users incur the same derivation. Sessions are opaque hashed tokens with HttpOnly/SameSite Strict cookies and HTTPS Secure attachment. Authenticated writes use Origin and CSRF gates; roles/memberships re-resolve per request. SQL values are parameterized. Commerce uses atomic transactions, version checks and request idempotency. Evidence downloads enforce entity authorization and session-bound signed grants, and remote content is checked against recorded byte length/hash. Reports escape HTML and guard spreadsheet formulas. Legacy AI is founder-only, opt-in, fixed Google endpoint and bounded/time-limited. Supabase snapshot transport is HTTPS, service-only, checksummed, bounded and CAS committed before releasing success/cookies; network failure does not create an empty authority fallback. Current source URL validation makes no network request, so private-DNS SSRF should not be asserted as a current fetch exploit.
