# ABANGCOLEK PLATFORM Review — 16 October 2026

## Scope

Read-only review of the repository guidance and current-authority documentation. The shell could not be used because device ACL application returned `Access is denied`; therefore no Git diff, test run, build, or live runtime check was performed.

## Findings

### 1. High — current test-count claims contradict each other

The repository presents at least three incompatible totals:

- `README.md:73` says **210 tests**, **1,199 assertions**, **47 files**.
- `docs/handover/CAPABILITY-MATRIX.md:47` says **210 unit tests**, **24 browser cases**, and **6 runtime checks**.
- `docs/handover/AGENT-HANDOVER-A-Z.md:45` says **260 tests**, **1,595 assertions**, **59 files**.
- `docs/ABANGCOLEK-SOURCE-OF-TRUTH.md:3` and `docs/PROJECT-ALIGNMENT-BACKLOG.md:3` also claim **260 tests / 1,595 assertions**.

**Risk:** reviewers and release operators cannot determine which verification receipt is authoritative. A stale lower count may incorrectly imply that the newer implementation was not tested; a stale higher count may overstate verification.

**Recommendation:** choose one fresh command output as the single receipt, record its timestamp/commit, and update all current-authority documents. Historical counts should be explicitly labelled as snapshots.

### 2. High — runtime status is inconsistent across current documents

The documents alternately describe the local runtime as running and stopped:

- `README.md:12` says the preview/API are `RUNNING_LOCAL`.
- `docs/ABANGCOLEK-SOURCE-OF-TRUTH.md:20` says UI/API are running locally.
- `docs/runbooks/platform-recovery.md:3,45,47` says they are currently running.
- The handover contains an older stopped-runtime snapshot (`AGENT-HANDOVER-A-Z.md:49-60`) but labels it as historical.

**Risk:** an operator may launch a second instance, act on stale PID assumptions, or treat a historical receipt as current. The runbook warns against this exact failure mode.

**Recommendation:** add a prominent `STATUS AS OF <timestamp>` block to every current entry, link to one live receipt, and remove unqualified present-tense claims from documents that mix historical and current snapshots.

### 3. Medium — capability matrix has an outdated document count/status receipt

`docs/handover/CAPABILITY-MATRIX.md:1-3` is dated 3 October, while `MARKDOWN-ALIGNMENT-REGISTER.md:8-12,47` reports later 4 October document counts and implementation receipts. The matrix also contains older AGY and implementation snapshots that are easy to read as current capability evidence.

**Risk:** capability discovery may overstate or understate what was actually verified in the current environment.

**Recommendation:** mark the matrix as a dated snapshot in its title and add a short current-state pointer to the Source of Truth/backlog. Do not use it as proof of current connected-provider status without a fresh receipt.

### 4. Medium — production readiness remains clearly unverified

The README says production has no accepted receipt and local fixes were not pushed (`README.md:21`); the Source of Truth says production workflows failed and no production receipt exists (`docs/ABANGCOLEK-SOURCE-OF-TRUTH.md:22`). This is correctly disclosed, but it conflicts with broad “completed” language elsewhere such as “all 18 work items completed.”

**Risk:** “implementation complete” may be interpreted as “production ready.”

**Recommendation:** consistently separate `DONE_LOCAL` from `PRODUCTION_VERIFIED`, especially in headings and summary tables.

## Overall assessment

**Documentation review: needs correction before release or handover.** The architecture and safety boundaries are repeatedly stated and generally clear, but the contradictory verification totals and mixed runtime snapshots are release-process risks. No code-level defect can be confirmed from this read-only pass.
